# TreckTren

ИИ-тренер для зала: PWA, где всё строится вокруг карточки атлета. Сейчас готова неделя 1 по ТЗ: каркас, схема БД, авторизация с согласием и карточка атлета с историей версий.

## Режим входа: сейчас демо

Пока регистрация и вход выключены: `AUTH_MODE=demo`, все сразу попадают в один тестовый аккаунт `demo@trecktren.local`, и все, у кого есть ссылка, видят одни и те же данные.

| `AUTH_MODE`               | Что происходит                                                                                                                                                                |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `demo`                    | Экранов входа и регистрации нет, клиент сам получает сессию тестового аккаунта через `POST /auth/demo`. Регистрация, вход и удаление аккаунта отвечают 403 `FEATURE_DISABLED` |
| `password` (по умолчанию) | Обычные регистрация с согласием и вход по email и паролю                                                                                                                      |

Чтобы вернуть регистрацию и вход, убери `AUTH_MODE=demo` из переменных Railway (или поставь `password`) — код менять не нужно. Старые сессии тестового аккаунта после этого перестанут продлеваться, а войти в него по паролю нельзя.

## Что внутри

| Папка             | Что это                                                                                                      |
| ----------------- | ------------------------------------------------------------------------------------------------------------ |
| `packages/shared` | Общие схемы zod: карточка атлета, запросы авторизации, merge patch, коды ошибок, русские сообщения валидации |
| `apps/server`     | API на Express 5 + PostgreSQL, миграции в `migrations/*.sql`                                                 |
| `apps/client`     | React 19 + Vite 8, мобильная вёрстка под 390 px                                                              |

Стек: Node.js 22, TypeScript 6, Express 5, PostgreSQL 16, zod 4, React 19, TanStack Query, Vitest.

## Запуск на Windows

1. Поставь [Node.js 22 LTS](https://nodejs.org/) (нужна 22.12 или новее) и [PostgreSQL 16](https://www.postgresql.org/download/windows/). При установке PostgreSQL запомни пароль пользователя `postgres`.
2. Создай две базы в pgAdmin или в SQL Shell (psql):
   ```sql
   CREATE DATABASE trektren_dev;
   CREATE DATABASE trektren_test;
   ```
3. В корне проекта:
   ```powershell
   npm install
   copy apps\server\.env.example apps\server\.env
   copy apps\server\env.test.example apps\server\.env.test
   ```
4. В `apps/server/.env` впиши пароль от `postgres` в `DATABASE_URL` и сгенерируй секрет для `JWT_ACCESS_SECRET`:
   ```powershell
   node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"
   ```
   В `apps/server/.env.test` поправь пароль в `TEST_DATABASE_URL`.
5. Накати схему и запусти:
   ```powershell
   npm run db:migrate
   npm run dev
   ```
   Клиент: http://localhost:5173, API: http://localhost:3000/api/v1. Vite проксирует `/api` на сервер, поэтому refresh-cookie работает как в проде.

Проект лучше держать вне OneDrive (например, `C:\dev\TreckTren`): `node_modules` — это тысячи файлов, синхронизация их тормозит.

## План тренировок

Человек отмечает в календаре дни, когда может тренироваться (до 8 недель вперёд). Дальше:

1. Из базы упражнений (65 штук, миграция `1762900000000_exercise_base.sql`) убираются те, для которых нет оборудования, которые задевают травмы или стоят в списке «что нельзя».
2. ИИ строит шаблон блока: сплит, тренировки A/B/C…, подходы и повторы, 3–5 недель накопления с запасом повторов от 3 к 1. Ответ проверяется схемой и по базе; если не прошёл — одна попытка исправления. Без ключа, при ошибке или таймауте ИИ шаблон собирается по правилам (`modules/plan/rules.ts`), а на экране плана пишется почему.
3. Код раскладывает шаблон по датам: неделя считается от понедельника первой даты, после накопления — неделя разгрузки. Если между тренировками меньше 2 дней и нагружаются те же крупные мышцы, ставится другая тренировка из ротации или эта облегчается. После перерыва 10+ дней веса −10%.
4. Веса считаются при каждом чтении плана от текущих максимумов (обратная формула Эпли с запасом, вниз до шага снаряда). В «Силовых» по каждому упражнению — реальный максимум на 1 раз и/или рабочий подход; реальный максимум важнее расчёта. Остальные упражнения со свободным весом считаются через соотношения с приседом, становой, жимами и тягой (`ref_slug`, `ref_ratio` в базе), гантели — на руку. Блоки и тренажёры — подбор по запасу. Нет данных совсем — оценка по весу тела и стажу.
5. ИИ достаёт из текста анкеты и комментария максимумы, рабочие веса и цели и пишет их в «Силовые» туда, где пусто.
6. Прогноз максимумов на конец блока (стаж, цель, возраст, отстающие движения) и проходка — последняя тренировка разгрузочной недели. Результат сверяется с прогнозом и становится новым максимумом.
7. Диагностика: соотношения максимумов (присед/становая, жим/присед, жим стоя/жим лёжа, тяга/жим) находят отстающее движение, тренер даёт тесты, по результатам — вывод в «Слабые места» и плашка «перестрой план».

ИИ подключается переменными, код менять не нужно — подходит любой OpenAI-совместимый API:

| Переменная       | По умолчанию                                              | Что это                                               |
| ---------------- | --------------------------------------------------------- | ----------------------------------------------------- |
| `AI_API_KEY`     | —                                                         | Ключ провайдера. Пусто — план по правилам             |
| `AI_BASE_URL`    | `https://generativelanguage.googleapis.com/v1beta/openai` | Gemini; для Groq, OpenRouter, Claude — их адрес       |
| `AI_MODEL`       | `gemini-3.5-flash`                                        | Модель                                                |
| `AI_JSON_MODE`   | `json_schema`                                             | Если провайдер не знает режим, клиент сам понизит его |
| `AI_TIMEOUT_MS`  | `90000`                                                   | Сколько ждать ответа                                  |
| `AI_DAILY_LIMIT` | `30`                                                      | Построений плана с ИИ на пользователя в сутки         |

Бесплатный уровень Gemini подходит только для разработки и своих тестов: Google может использовать эти запросы для улучшения моделей, а для пользователей из ЕС нужен платный уровень. Перед запуском для других людей переключи ключ на платный проект.

## API

Все пути с префиксом `/api/v1`. Ошибки в формате `{ "error": { "code", "message", "details?" } }`.

| Метод и путь                     | Что делает                                                                              |
| -------------------------------- | --------------------------------------------------------------------------------------- |
| `GET /auth/mode`                 | Режим входа: `{ "mode": "demo" }` или `{ "mode": "password" }`                          |
| `POST /auth/demo`                | Только в демо: сессия тестового аккаунта                                                |
| `POST /auth/register`            | Регистрация: email, пароль от 8 символов, `healthConsent: true`, `adultConfirmed: true` |
| `POST /auth/login`               | Вход                                                                                    |
| `POST /auth/refresh`             | Новый access-токен по refresh-cookie, старый refresh отзывается                         |
| `POST /auth/logout`              | Выход, отзыв refresh-токена                                                             |
| `GET /me`                        | Текущий пользователь                                                                    |
| `DELETE /account`                | Удаление аккаунта и всех данных, нужен пароль                                           |
| `GET /card`                      | Карточка атлета и её версия                                                             |
| `PATCH /card`                    | Правка: `{ patch, baseVersion?, reason? }`                                              |
| `GET /card/versions`             | История версий                                                                          |
| `GET /card/versions/:v`          | Снимок карточки в версии `v`                                                            |
| `POST /card/versions/:v/restore` | Откат: снимок версии `v` становится новой версией                                       |
| `GET /exercises`                 | База упражнений                                                                         |
| `GET /plan`                      | Текущий блок и тренировки по датам с рабочими весами                                    |
| `POST /plan/generate`            | Построить или перестроить план: `{ dates, comment? }`                                   |
| `PUT /plan/schedule`             | Новые дни для текущего блока: `{ dates }`, без ИИ                                       |
| `PUT /strength`                  | «Силовые»: `{ lifts: [{ slug, testedKg?, working? }], targets? }`, `null` удаляет       |
| `POST /plan/sessions/:id/result` | Результат проходки: `{ lifts: [{ slug, weightKg, reps }] }` → сверка и новые максимумы  |
| `GET /diagnostics`               | Отстающие движения по соотношениям и тесты к ним                                        |
| `POST /diagnostics/:findingId`   | Результаты тестов `{ results: { testId: число } }` → вывод в «Слабые места»             |

## Решения, которые стоит знать

- **Правки карточки — JSON Merge Patch (RFC 7386).** Объекты сливаются, `null` удаляет поле, массивы заменяются целиком. Каждая правка создаёт версию с патчем и полным снимком, поэтому откат не переписывает историю.
- **Кто что правит.** Человек меняет 10 разделов из `USER_EDITABLE_SECTIONS`. Силовые, прогноз и заметки тренера через `PATCH /card` не меняются (403): их пишут код и ИИ через `applyCardPatch` с нужным `allowedSections`.
- **Конфликты.** Клиент шлёт `baseVersion`. Если карточку уже поменяли на другом устройстве, сервер вернёт 409, и клиент подтянет свежую версию.
- **Схемы строгие.** Неизвестный ключ в карточке — ошибка 422, а не тихое сохранение опечатки.
- **Сессии.** Access-токен живёт 15 минут и хранится только в памяти вкладки. Refresh-токен лежит в httpOnly-cookie с путём `/api/v1/auth`, в базе — только его SHA-256. Каждый refresh меняет токен. Повтор старого токена позже 10 секунд считается кражей и отзывает все сессии пользователя.
- **Приватность.** В логах только метод, путь, статус и время. Тела запросов и query не пишутся. Удаление аккаунта каскадом удаляет все таблицы пользователя.

## Прод

Прод живёт на Railway, проект `trecktren`: https://app-production-0b85540c.up.railway.app. Каждый пуш в `main` деплоится сам.

| Сервис     | Что это                                                                                                                                   |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `app`      | Этот репозиторий, сборщик Railpack, регион sfo. Один сервер отдаёт и API, и собранный клиент, поэтому cookie работает с `SameSite=Strict` |
| `Postgres` | Шаблон Railway PostgreSQL 18 с томом на 5 ГБ                                                                                              |

Настройки `app`:

- Сборка: `npm run build` из корня (Railpack запускает его сам), Node 22 через `RAILPACK_NODE_VERSION=22`.
- Перед запуском: `npm run db:migrate:prod -w @trektren/server` — миграции катятся до старта новой версии; если упали, деплой не переключается.
- Запуск: `npm start`, healthcheck: `/api/v1/health`. `NODE_ENV=production` Railpack ставит сам.
- Переменные: `DATABASE_URL=${{Postgres.DATABASE_URL}}` (внутренняя сеть, без SSL), `JWT_ACCESS_SECRET`, `PORT=8080`, `CLIENT_DIST_DIR=../client/dist`, `TRUST_PROXY=1`, `CORS_ORIGIN` — домен приложения, `COOKIE_SAMESITE=strict`, `AUTH_MODE=demo`, `AI_API_KEY` (ключ ИИ, его добавляют в Railway вручную).
